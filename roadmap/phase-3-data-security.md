# Phase 3: Data Security & Encryption

## Overview
Data security is paramount in cloud environments. This phase covers encryption strategies, key management, and AWS services for protecting data at rest and in transit.

## Learning Objectives
By the end of this phase, you will be able to:
- Implement encryption at rest and in transit
- Manage encryption keys with AWS KMS
- Secure S3 buckets comprehensively
- Use AWS Certificate Manager for TLS certificates
- Understand CloudHSM for compliance requirements
- Apply data classification principles

## Encryption Fundamentals

### Types of Encryption

```
┌──────────────────────────────────────────────┐
│  Encryption at Rest                          │
│  - Data stored on disk (S3, EBS, RDS, etc.) │
│  - Uses symmetric encryption (AES-256)       │
│  - Keys managed by AWS KMS or CloudHSM       │
└──────────────────────────────────────────────┘

┌──────────────────────────────────────────────┐
│  Encryption in Transit                       │
│  - Data moving between systems               │
│  - Uses TLS/SSL (asymmetric + symmetric)     │
│  - Certificates managed by AWS ACM           │
└──────────────────────────────────────────────┘
```

### Encryption Key Hierarchy

```
┌─────────────────────────────────────────────┐
│  Customer Master Key (CMK) in KMS           │
│  - Never leaves KMS                         │
│  - Used to encrypt/decrypt Data Keys        │
└────────────┬────────────────────────────────┘
             ↓
┌─────────────────────────────────────────────┐
│  Data Encryption Key (DEK)                  │
│  - Generated by KMS                         │
│  - Encrypts actual data                     │
│  - Stored encrypted alongside data          │
└────────────┬────────────────────────────────┘
             ↓
┌─────────────────────────────────────────────┐
│  Encrypted Data (S3 object, EBS volume)     │
│  - Encrypted with DEK                       │
│  - Encrypted DEK stored with data           │
└─────────────────────────────────────────────┘
```

This is called **Envelope Encryption**.

## AWS Key Management Service (KMS)

### KMS Key Types

| Type | Description | Use Case | Rotation |
|------|-------------|----------|----------|
| **AWS Managed Keys** | Created/managed by AWS | Default encryption for AWS services | Automatic (3 years) |
| **Customer Managed Keys** | You create and manage | Full control, custom key policies | Manual or automatic (yearly) |
| **AWS Owned Keys** | Owned by AWS services | No visibility to customer | Managed by AWS |
| **Custom Key Store** | Keys in CloudHSM | Compliance (FIPS 140-2 Level 3) | Manual |

### KMS Key Policy

**Default key policy (allows root account):**
```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "Enable IAM User Permissions",
      "Effect": "Allow",
      "Principal": {
        "AWS": "arn:aws:iam::123456789012:root"
      },
      "Action": "kms:*",
      "Resource": "*"
    }
  ]
}
```

**Custom key policy (specific permissions):**
```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "Allow use of the key for encryption",
      "Effect": "Allow",
      "Principal": {
        "AWS": "arn:aws:iam::123456789012:role/AppRole"
      },
      "Action": [
        "kms:Encrypt",
        "kms:Decrypt",
        "kms:GenerateDataKey"
      ],
      "Resource": "*"
    },
    {
      "Sid": "Allow attachment of persistent resources",
      "Effect": "Allow",
      "Principal": {
        "AWS": "arn:aws:iam::123456789012:role/AppRole"
      },
      "Action": [
        "kms:CreateGrant",
        "kms:ListGrants",
        "kms:RevokeGrant"
      ],
      "Resource": "*",
      "Condition": {
        "Bool": {
          "kms:GrantIsForAWSResource": "true"
        }
      }
    }
  ]
}
```

## S3 Security Deep Dive

### S3 Security Layers

```
┌─────────────────────────────────────────────┐
│  Layer 1: Block Public Access (Account)    │
│  - Prevents accidental public exposure      │
└────────────┬────────────────────────────────┘
             ↓
┌─────────────────────────────────────────────┐
│  Layer 2: Bucket Policy                     │
│  - Resource-based policy                    │
│  - Controls bucket-level access             │
└────────────┬────────────────────────────────┘
             ↓
┌─────────────────────────────────────────────┐
│  Layer 3: IAM Policies                      │
│  - Identity-based policies                  │
│  - Controls user/role access                │
└────────────┬────────────────────────────────┘
             ↓
┌─────────────────────────────────────────────┐
│  Layer 4: Encryption                        │
│  - SSE-S3, SSE-KMS, SSE-C                   │
│  - Server-side or client-side               │
└────────────┬────────────────────────────────┘
             ↓
┌─────────────────────────────────────────────┐
│  Layer 5: Versioning + Object Lock          │
│  - Protect against deletion/modification    │
│  - WORM (Write Once Read Many)              │
└─────────────────────────────────────────────┘
```

### S3 Encryption Options

#### 1. SSE-S3 (Server-Side Encryption with S3 Managed Keys)
- **Key management**: AWS manages keys
- **Encryption**: AES-256
- **Cost**: Free
- **Use case**: Default encryption, simple use cases

```bash
aws s3api put-object \
  --bucket my-bucket \
  --key file.txt \
  --server-side-encryption AES256 \
  --body file.txt
```

#### 2. SSE-KMS (Server-Side Encryption with KMS)
- **Key management**: AWS KMS
- **Encryption**: AES-256
- **Cost**: KMS API calls (~$0.03/10,000 requests)
- **Use case**: Audit trail, key rotation, fine-grained access control

```bash
aws s3api put-object \
  --bucket my-bucket \
  --key file.txt \
  --server-side-encryption aws:kms \
  --ssekms-key-id arn:aws:kms:us-east-1:123456789012:key/xxxxx \
  --body file.txt
```

#### 3. SSE-C (Server-Side Encryption with Customer-Provided Keys)
- **Key management**: Customer manages keys
- **Encryption**: AES-256
- **Use case**: Customer controls encryption keys outside AWS

```bash
aws s3api put-object \
  --bucket my-bucket \
  --key file.txt \
  --sse-customer-algorithm AES256 \
  --sse-customer-key <base64-encoded-key> \
  --body file.txt
```

#### 4. Client-Side Encryption
- **Encryption**: Before uploading to S3
- **Key management**: Customer
- **Use case**: Maximum control, end-to-end encryption

## Hands-On Labs

### Lab 1: Create and Use KMS Keys

**Objective**: Create a customer-managed KMS key and use it for encryption.

**Steps:**

1. **Create KMS Key:**
```bash
aws kms create-key \
  --description "Production data encryption key" \
  --key-policy file://key-policy.json
```

2. **Create Alias:**
```bash
aws kms create-alias \
  --alias-name alias/production-key \
  --target-key-id <key-id>
```

3. **Enable Automatic Key Rotation:**
```bash
aws kms enable-key-rotation \
  --key-id <key-id>
```

4. **Encrypt Data:**
```bash
echo "Sensitive data" > plaintext.txt

aws kms encrypt \
  --key-id alias/production-key \
  --plaintext fileb://plaintext.txt \
  --output text \
  --query CiphertextBlob | base64 --decode > encrypted.bin
```

5. **Decrypt Data:**
```bash
aws kms decrypt \
  --ciphertext-blob fileb://encrypted.bin \
  --output text \
  --query Plaintext | base64 --decode
```

6. **Audit Key Usage:**
```bash
# Check CloudTrail for KMS API calls
aws cloudtrail lookup-events \
  --lookup-attributes AttributeKey=ResourceName,AttributeValue=<key-id> \
  --max-results 10
```

### Lab 2: Secure S3 Bucket

**Objective**: Implement comprehensive S3 bucket security.

**Steps:**

1. **Create Bucket:**
```bash
aws s3api create-bucket \
  --bucket my-secure-bucket-12345 \
  --region us-east-1
```

2. **Enable Block Public Access:**
```bash
aws s3api put-public-access-block \
  --bucket my-secure-bucket-12345 \
  --public-access-block-configuration \
    BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true
```

3. **Enable Default Encryption:**
```bash
aws s3api put-bucket-encryption \
  --bucket my-secure-bucket-12345 \
  --server-side-encryption-configuration '{
    "Rules": [{
      "ApplyServerSideEncryptionByDefault": {
        "SSEAlgorithm": "aws:kms",
        "KMSMasterKeyID": "arn:aws:kms:us-east-1:123456789012:key/xxxxx"
      },
      "BucketKeyEnabled": true
    }]
  }'
```

4. **Enable Versioning:**
```bash
aws s3api put-bucket-versioning \
  --bucket my-secure-bucket-12345 \
  --versioning-configuration Status=Enabled
```

5. **Enable Access Logging:**
```bash
aws s3api put-bucket-logging \
  --bucket my-secure-bucket-12345 \
  --bucket-logging-status '{
    "LoggingEnabled": {
      "TargetBucket": "my-logging-bucket",
      "TargetPrefix": "logs/my-secure-bucket/"
    }
  }'
```

6. **Apply Bucket Policy (Enforce TLS):**
```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "DenyUnencryptedTransport",
      "Effect": "Deny",
      "Principal": "*",
      "Action": "s3:*",
      "Resource": [
        "arn:aws:s3:::my-secure-bucket-12345",
        "arn:aws:s3:::my-secure-bucket-12345/*"
      ],
      "Condition": {
        "Bool": {
          "aws:SecureTransport": "false"
        }
      }
    }
  ]
}
```

```bash
aws s3api put-bucket-policy \
  --bucket my-secure-bucket-12345 \
  --policy file://bucket-policy.json
```

7. **Enable Object Lock (Optional - WORM):**
```bash
# Must be enabled at bucket creation
aws s3api create-bucket \
  --bucket my-worm-bucket-12345 \
  --region us-east-1 \
  --object-lock-enabled-for-bucket

# Set default retention
aws s3api put-object-lock-configuration \
  --bucket my-worm-bucket-12345 \
  --object-lock-configuration '{
    "ObjectLockEnabled": "Enabled",
    "Rule": {
      "DefaultRetention": {
        "Mode": "GOVERNANCE",
        "Days": 90
      }
    }
  }'
```

### Lab 3: TLS/SSL with AWS Certificate Manager

**Objective**: Provision and use SSL certificates for your domain.

**Steps:**

1. **Request Certificate:**
```bash
aws acm request-certificate \
  --domain-name example.com \
  --subject-alternative-names www.example.com \
  --validation-method DNS
```

2. **Validate Domain Ownership:**
```bash
# Get DNS validation records
aws acm describe-certificate \
  --certificate-arn arn:aws:acm:us-east-1:123456789012:certificate/xxxxx

# Add CNAME records to your DNS
# AWS will automatically validate once records are detected
```

3. **Attach to Load Balancer:**
```bash
aws elbv2 create-listener \
  --load-balancer-arn arn:aws:elasticloadbalancing:us-east-1:123456789012:loadbalancer/app/my-alb/xxxxx \
  --protocol HTTPS \
  --port 443 \
  --certificates CertificateArn=arn:aws:acm:us-east-1:123456789012:certificate/xxxxx \
  --default-actions Type=forward,TargetGroupArn=arn:aws:elasticloadbalancing:us-east-1:123456789012:targetgroup/my-tg/xxxxx
```

4. **Configure SSL Policy:**
```bash
aws elbv2 modify-listener \
  --listener-arn arn:aws:elasticloadbalancing:us-east-1:123456789012:listener/app/my-alb/xxxxx \
  --ssl-policy ELBSecurityPolicy-TLS-1-2-2017-01
```

### Lab 4: RDS Encryption

**Objective**: Enable encryption for RDS database.

**Steps:**

1. **Create Encrypted RDS Instance:**
```bash
aws rds create-db-instance \
  --db-instance-identifier mydb-encrypted \
  --db-instance-class db.t3.micro \
  --engine postgres \
  --master-username admin \
  --master-user-password MySecurePassword123! \
  --allocated-storage 20 \
  --storage-encrypted \
  --kms-key-id arn:aws:kms:us-east-1:123456789012:key/xxxxx
```

2. **Enable Automatic Backups (Encrypted):**
```bash
aws rds modify-db-instance \
  --db-instance-identifier mydb-encrypted \
  --backup-retention-period 7 \
  --preferred-backup-window "03:00-04:00"
```

**Note**: Cannot enable encryption on existing unencrypted RDS instance. Must:
- Create snapshot
- Copy snapshot with encryption
- Restore from encrypted snapshot

### Lab 5: EBS Encryption

**Objective**: Enable default EBS encryption.

**Steps:**

1. **Enable Default EBS Encryption:**
```bash
aws ec2 enable-ebs-encryption-by-default \
  --region us-east-1
```

2. **Set Default KMS Key:**
```bash
aws ec2 modify-ebs-default-kms-key-id \
  --kms-key-id arn:aws:kms:us-east-1:123456789012:key/xxxxx \
  --region us-east-1
```

3. **Create Encrypted Volume:**
```bash
aws ec2 create-volume \
  --availability-zone us-east-1a \
  --size 10 \
  --volume-type gp3 \
  --encrypted \
  --kms-key-id arn:aws:kms:us-east-1:123456789012:key/xxxxx
```

4. **Encrypt Existing Volume:**
```bash
# Create snapshot of unencrypted volume
aws ec2 create-snapshot \
  --volume-id vol-xxxxx \
  --description "Snapshot before encryption"

# Copy snapshot with encryption
aws ec2 copy-snapshot \
  --source-region us-east-1 \
  --source-snapshot-id snap-xxxxx \
  --encrypted \
  --kms-key-id arn:aws:kms:us-east-1:123456789012:key/xxxxx \
  --description "Encrypted snapshot"

# Create encrypted volume from snapshot
aws ec2 create-volume \
  --snapshot-id snap-encrypted-xxxxx \
  --availability-zone us-east-1a
```

## CloudHSM

### When to Use CloudHSM vs KMS

| Feature | AWS KMS | AWS CloudHSM |
|---------|---------|--------------|
| **Compliance** | FIPS 140-2 Level 2 | FIPS 140-2 Level 3 |
| **Key Control** | AWS manages HSM | Customer manages HSM |
| **Multi-Tenancy** | Shared (isolated) | Single-tenant |
| **Cost** | $1/key/month + API calls | $1.60/hour per HSM (~$1,150/month) |
| **Use Case** | Most workloads | High compliance requirements |
| **Crypto Operations** | Limited to AWS services | Full control, custom crypto |

**CloudHSM Use Cases:**
- Regulatory compliance (PCI-DSS, HIPAA, etc.)
- Offload SSL/TLS processing
- Protect private keys for Certificate Authority
- Database encryption (Oracle TDE, SQL Server EKM)

## Best Practices

### Encryption Best Practices
- [ ] Enable encryption by default for all data stores
- [ ] Use customer-managed KMS keys for sensitive data
- [ ] Enable automatic key rotation (KMS)
- [ ] Enforce TLS 1.2+ for data in transit
- [ ] Use AWS Certificate Manager for certificate management
- [ ] Never store encryption keys in code or config files

### S3 Security Best Practices
- [ ] Enable Block Public Access (account and bucket level)
- [ ] Enable default encryption (SSE-KMS recommended)
- [ ] Enable versioning for critical data
- [ ] Use Object Lock for compliance (WORM)
- [ ] Enable access logging
- [ ] Use VPC endpoints to avoid internet traffic
- [ ] Implement least privilege bucket policies
- [ ] Enable MFA Delete for critical buckets
- [ ] Regular access reviews with S3 Access Analyzer

### Key Management Best Practices
- [ ] Separate keys by environment (dev, staging, prod)
- [ ] Use different keys for different data classifications
- [ ] Enable CloudTrail logging for all key usage
- [ ] Set up CloudWatch alarms for suspicious key activity
- [ ] Document key policies and access patterns
- [ ] Regular key rotation (automatic or manual)
- [ ] Backup key policies

## Data Classification

### Classification Levels

| Level | Description | Examples | Controls |
|-------|-------------|----------|----------|
| **Public** | Can be disclosed publicly | Marketing materials | Basic encryption |
| **Internal** | Internal use only | Employee directories | Encryption, access control |
| **Confidential** | Sensitive business data | Financial reports | Strong encryption, logging, MFA |
| **Restricted** | Highly sensitive | PII, PHI, PCI data | KMS encryption, strict access, audit |

### Tagging Strategy for Data Classification

```bash
# Tag S3 bucket with classification
aws s3api put-bucket-tagging \
  --bucket my-bucket \
  --tagging 'TagSet=[{Key=DataClassification,Value=Confidential},{Key=Environment,Value=Production}]'

# Tag KMS key with classification
aws kms tag-resource \
  --key-id arn:aws:kms:us-east-1:123456789012:key/xxxxx \
  --tags TagKey=DataClassification,TagValue=Restricted
```

## Exam Tips

1. **KMS**: Regional service, keys don't leave the region
2. **Envelope Encryption**: KMS encrypts DEK, DEK encrypts data
3. **S3 Default Encryption**: Applied to new objects only
4. **SSE-KMS**: Adds audit trail and access control via key policies
5. **CloudHSM**: For FIPS 140-2 Level 3 compliance
6. **TLS**: Use ACM for certificate management, don't manage manually
7. **Encryption at Rest**: Should be enabled for all data stores
8. **MFA Delete**: Requires versioning to be enabled first
